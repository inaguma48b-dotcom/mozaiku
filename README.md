# モザイクツール

画像を**一切サーバーに送らず**、ブラウザ内だけでモザイク・ぼかし・黒塗りをかけるツール。
APIキー不要・アカウント不要・依存ライブラリゼロ。パスワードで元に戻せる**可逆モザイク**に対応。

## 使い方

### そのまま使う
`index.html` をダブルクリックしてブラウザで開くだけ。可逆モザイク（暗号化）もこの状態で動きます。

### ローカルサーバーで使う（PWA・オフライン起動を試す場合）
Service Worker は `file://` では動かないため、`http://localhost` で開きます。

```bash
node mosaic-tool/server.js
```

→ http://localhost:5173

## 機能

| 分類 | 内容 |
|---|---|
| 読み込み | ファイル選択（複数可） / ドラッグ&ドロップ / Ctrl+V 貼り付け / PWAでの「このアプリで開く」 |

| 表示 | フィット / 100% / ピンチズーム / Space+ドラッグでパン / Ctrl+ホイール |
| 保存 | PNG（Exif自動削除）、JPEG、複数枚はZIP |
| PWA | インストール・オフライン起動対応 |

## 複数枚の扱い

複数枚を放り込むと下部にサムネイルが並びます。切り替えると編集結果はPNG Blobへ退避されるため、
フル解像度のキャンバスがメモリに積み上がりません（履歴は画像ごとにリセットされます）。

**矩形の加工を全画像へ複製** は、矩形ツールで行った加工だけを、同じサイズの画像の同じ座標へ適用します。
スクリーンショットの決まった位置（アカウント名、IPアドレス等）をまとめて隠す用途向けです。
ブラシの加工は画像ごとに位置が違うため複製対象外です。

**全部保存(ZIP)** はライブラリを使わず自前でZIP（無圧縮 store）を組み立てています。
PNG/JPEGは既に圧縮済みなので、再圧縮しなくてもサイズはほぼ変わりません。

## 顔の自動検出（任意機能）

初期状態では無効です。有効にするには一度だけ取得スクリプトを実行します。

```bash
node mosaic-tool/tools/fetch-pico.js
```

pico.js と学習済みカスケードが `vendor/` に入り、サイドバーの「顔を検出して隠す」が使えるようになります。
検出はすべてブラウザ内で完結し、通信は発生しません（取得スクリプトの実行時のみ通信します）。

- 検出は**原画に対して**行います。既にモザイクを掛けた後でも取りこぼしません
- 検出した顔は、そのとき選んでいる効果（モザイク／ぼかし／黒塗り）で隠します
- 複数箇所を隠しても**1回のUndoでまとめて戻せます**
- 「検出の厳しさ」を甘くすると拾う範囲が広がります
- 複数枚のときは「全画像の顔を検出して隠す」で一括処理できます

**取得物のサイズ**：`pico.js` 5.5KB、カスケード 234KB（base64埋め込み版 312KB）。
`vendor/` を消せば機能はボタンごと無効化され、本体はそのまま動きます。

**注意**：正面顔向けの検出器です。横顔・後ろ姿・大きく隠れた顔は取りこぼします。
**検出結果を鵜呑みにせず、必ず目視で確認してください。**

ライセンス表記は [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) を参照してください（いずれもMIT）。

なお `index.html` を `file://` で直接開いた場合、ブラウザによっては
`vendor/` 内のスクリプト読み込みが制限され、顔検出だけ無効になることがあります。
その場合はローカルサーバー経由か、公開したhttps環境で使ってください（他の機能は影響を受けません）。

## 可逆モザイクの仕組み

```
保存時
  1. 隠した領域の「原画ピクセル」を1枚のパッチPNGにまとめる
  2. AES-GCM-256 で暗号化（鍵 = PBKDF2-SHA256(パスワード, salt, 600,000回)）
  3. 出力PNGのカスタムチャンク msKd に同梱
     → 通常のビューアでは「ただのモザイク画像」として開ける

復元時
  4. チャンクを取り出しパスワードで復号
  5. 元領域を貼り戻す（ピクセル単位で完全一致）
```

コンテナ形式：

```
"MOSAICR1"(8B) | headerLen(4B, BE) | header JSON | ciphertext
header = { v, w, h, salt, iv, kdf, iter, alg }
平文    = layoutLen(4B, BE) | layout JSON | パッチPNG
```

反復回数はヘッダの `iter` から読むため、将来値を変えても古いファイルは開けます。
複数枚の一括保存では鍵導出を1回にまとめ、画像ごとに異なるIVを使います。

### 制約（重要）

- **SNSにアップすると復元できなくなります。** 各サービスが画像を再エンコードするため、
  埋め込んだチャンクは消えます。ファイルを直接受け渡す用途で使ってください。
  保険として「鍵データを別ファイル(.mkey)にも保存」を有効にすると、
  画像が再圧縮されても `.mkey` 側から復元できます（画像サイズが変わっていない場合のみ）。
- **リサイズ・切り抜きをした画像は復元できません。** 座標が合わなくなるためです。
  保存時のサイズと違う場合はエラーを出します。
- **パスワードを忘れた場合、復旧手段はありません。**
- 保存形式は PNG 固定です（JPEG は再圧縮で画素が変わるため）。

### 「他人が作ったモザイク」は解除できません

このツールの「解除」は、**自分でこのツールを使ってかけたモザイク**を、
自分のパスワードで戻す機能です。
一般的なモザイク画像は元の情報が破壊されているため、原理的に復元できません。
（AI超解像で「それらしい絵」を作ることはできますが、それは復元ではありません。）

## 公開する場合

静的ファイルのみなので、そのまま置くだけで動きます。

- GitHub Pages … リポジトリに push → Settings > Pages で公開
- Cloudflare Pages / Netlify / Vercel … ビルドコマンドなし、出力ディレクトリにこのフォルダを指定

PWA として動かすには **https** 必須です（上記はいずれも自動でhttps）。

## ファイル構成

```
mosaic-tool/
├── index.html               アプリ本体（顔検出以外はこれ単体で動く）
├── manifest.json            PWA設定
├── sw.js                    Service Worker（オフライン用）
├── server.js                開発用の静的サーバー（Node標準のみ）
├── icons/                   アイコン一式
├── vendor/                  顔検出用（fetch-pico.js が生成。無くても本体は動く）
├── THIRD-PARTY-NOTICES.md   vendor/ のライセンス表記
└── tools/
    ├── make-icons.js        アイコン生成（Node標準のみ）
    ├── fetch-pico.js        顔検出データの取得
    └── testdata/            顔検出の確認用画像（配布物には含めない）
```

## 検証済みの動作

ブラウザ上で自動テストを実行して確認済み：

- モザイクのブロック整列（同一ブロック内が均一・隣接ブロックは別色）
- 選択範囲外が無傷であること、出力が完全不透明であること
- Undo/Redo の往復、全操作Undo後に原画とピクセル一致
- 2本指操作に切り替わったときの描きかけ中断・復帰
- 拡大縮小時の焦点固定（スクロール余地がある場合の誤差 0.1px）
- 可逆モザイクの往復（**復元結果が原画とピクセル完全一致**）
- 誤ったパスワードの拒否、画像サイズ不一致の検出
- チャンクを埋め込んだPNGが一般的なビューアでデコード可能であること
- 複数枚の切り替えで各画像の加工が保持されること
- 実ポインタ操作での矩形記録と、同サイズ画像への複製（別サイズはスキップ）
- ZIPの中央ディレクトリ構造とCRC、各エントリがPNGとしてデコード可能であること
- 3枚一括の可逆保存 → 各ファイルが個別に元画像へ完全復元できること
- 顔検出：実写真（5人が写った集合写真）で **5人全員を検出、誤検出0**
- 顔検出の適用が1操作にまとまり、1回のUndoで戻ること
- 顔のない画像は変更されないこと（一括処理でも同様）
- Service Worker の登録とアプリシェルのキャッシュ（オフライン起動）

### 性能について

PBKDF2 60万回の鍵導出は実測 **79ms**、顔検出は 6.2MP（2880×2160）の画像で **234ms** です。
どちらも体感には影響しません。
（開発時の計測環境では `canvas.toBlob` のコールバックが一律1秒遅延しますが、
これは検証用ブラウザ側の制約で、通常のブラウザでは発生しません。）
